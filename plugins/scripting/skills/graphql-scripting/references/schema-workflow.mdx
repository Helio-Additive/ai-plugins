# Acquire the schema before generating code

The API schema is the source of truth. Do not ship a schema snapshot in this plugin.
For production, the docs examples identify `https://api.helioadditive.com/graphql/schema` as the SDL download and `https://api.helioadditive.com/graphql` as the request/introspection endpoint. Confirm the intended environment; do not substitute nightly MCP URLs.

Download to a temporary file with `curl --fail --show-error --location`, parse and validate it with a GraphQL implementation, then replace the working `schema.graphqls` only after success. An HTTP 200 HTML or JSON error body is not SDL. Record the source URL, UTC retrieval time and SHA-256 alongside the snapshot. Never record authentication headers. Refresh before a new integration or regeneration session; keep one snapshot fixed across all language generators in that session.

If direct SDL fails, request standard GraphQL introspection from the same environment and convert its `data` with GraphQL `buildClientSchema` and `printSchema`. Check HTTP status and GraphQL errors first. Introspection may be disabled or omit directive applications: prefer authoritative SDL when available. Use only documented authentication supplied securely; do not guess credentials or retry mutations to discover the schema.

The [schema documentation](https://docs.helioadditive.com/en/developers/schemas/) links an S3 SDL artifact. It is an explicit fallback, not proof of current deployment state. If using it or a cached snapshot, disclose its source and known age, obtain agreement when freshness matters, and do not silently treat it as current. If no validated schema is available, stop schema-dependent generation and report the exact failed fetch.

## Optional sectioned reference

Prefer inspecting SDL and its transitive referenced types directly. A sectioned Markdown reference can help navigation for a large schema, but must be derived from the same snapshot and include its hash and retrieval metadata. Never use a prose summary as the codegen input.

The docs repository actually renders Astro HTML, rather than generating Markdown:
[get-schema.ts](https://github.com/Helio-Additive/docs/blob/main/get-schema.ts) refreshes local SDL from Hive;
[src/utils/schema.ts](https://github.com/Helio-Additive/docs/blob/main/src/utils/schema.ts) reads it;
[src/utils/graphql.ts](https://github.com/Helio-Additive/docs/blob/main/src/utils/graphql.ts) parses it into sections;
[api.astro](https://github.com/Helio-Additive/docs/blob/main/src/pages/en/developers/api.astro) renders queries, mutations, subscriptions, objects, inputs, enums and scalars.
Do not copy registry credentials or its deployment-specific fetch setup.

If the user needs Markdown, generate those sections locally using GraphQL's schema/type APIs. Resolve root types from the schema, not assumed names; preserve exact type wrappers, argument defaults, descriptions, deprecations, interfaces, unions and directives. Escape descriptions as text. Regenerate whenever the schema hash changes. This extra presentation layer costs maintenance and may omit information, so retain links to the underlying SDL and keep it optional.

Custom scalar names alone do not establish wire formats. Read authoritative descriptions and examples before configuring generator scalar conversions. Stop and ask for the missing contract rather than mapping every unknown scalar to string or an unchecked type.

## Endpoint observation

During template validation on 2026-11-08, the documented direct SDL route returned
HTTP 404. The documented S3 fallback downloaded but genqlient rejected it: it contains a
form-feed control byte in a description. Full unauthenticated introspection
succeeded at `/graphql`, and the converted schema passed GraphQL schema validation
and genqlient generation/compilation. Never silently repair or use the
rejected artifact as authoritative SDL. This observation is
not a permanent endpoint contract or evidence of fallback freshness: always retry
the authoritative acquisition workflow for the selected environment, and disclose
any fallback before using it for real integration work.
