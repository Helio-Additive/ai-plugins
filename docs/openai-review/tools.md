# Hosted MCP audit, 26 November 2026

The authenticated Codex app server reported OAuth and exposed 18 Slicing and seven Dragon tools. Each advertised name was unique within its server, had a nonempty description and an object input schema that compiled with Ajv 2020. The two servers each expose their own upload tool. Scoped resources and the host's tool namespaces distinguish them. The inventory contained no declared output schemas or tool annotations. This inventory is a host view. Confirm the wire-level fields in the OpenAI scan before signing off.

Slicing returns structured object results for its GraphQL tools. Dragon also returns JSON as MCP text content. For example, the catalog contains a named collection and pagination, while a prepared plan has nested state and plan status. Consumers must handle tool errors and intermediate states. A successful HTTP request alone establishes neither a successful job nor an available file. Slicing source explicitly tests that it omits output schemas. Dragon's registration constructs definitions from name, description and input schema. Neither inspected registration path adds review hints. This repo packages references to the servers. The service and gateway owners control the advertised tool definitions. ## Behaviour to verify in the scan

These are proposed classifications for service owners, not claims about deployed annotations. Each named tool operates against a bounded Helio account, storage location or catalog. Use openWorldHint=false where that boundary is enforced. Confirm a presigned upload only targets Helio-controlled storage. Mark arbitrary external destinations open-world if a future implementation permits them.

| Tools | Inputs and observable effects | Annotation and retry review |
| --- | --- | --- |
| slicer_version, slicer_machines, slicer_filaments, slicer_processes | Version or catalog filters. Return version or compatible profile collections. | Read-only, non-destructive. |
| get_slicer_settings, validate_slicer_settings | Engine and, for validation, serialized overrides. Return allowed schema or structured issues. | Read-only, non-destructive. Invalid settings must never launch a job. |
| get_uploaded_file, list_uploaded_files, get_input_probe, get_slice, list_slices, get_gcode_timing | Owned ID or filters/pagination. Return file metadata, job/plate state, results or timing. | Read-only, non-destructive. Do not cross account boundaries or record signed links. |
| get_presigned_url (both) | Filename to temporary URL, key and MIME type. The subsequent HTTP PUT transfers bytes. | Issues a new write capability. Verify storage reservation with the owner before classifying read-only. Treat issuance and PUT separately. A new call can produce a different key. |
| create_input_probe, create_slice | Uploaded object or existing file ID. Register, queue or inspect persisted work. | Write, generally additive. Do not assert idempotence for arbitrary repeated requests. Inspect returned issues and exact plate errors. |
| rename_slice, rename_uploaded_file | Exact ID and new name overwrite user metadata. | Write; assess destructive overwrite. Reapplying the same name reaches the same visible value. Check audit/event side effects before asserting idempotence. |
| create_gcode_timing | Stable UUID, two original object keys, hashes and producer settings. Creates a timing job. | Write and additive. Reuse identity only with identical input under its documented recovery contract. |
| dragon_catalog, dragon_optimization_options | Resource/page or material ID. Return catalog entries or available account priorities. | Read-only and non-destructive. Distinguish unavailable options from transaction flows. |
| prepare_dragon_run | Stable identity, original upload/hash, printer, materials and operation. Registers input and persists the plan. | Write and additive. Poll with unchanged inputs. A preview that persists work cannot be labeled read-only. |
| start_dragon_run | Identity and explicit confirmation. Starts external compute for the prepared plan. | Write. Review irreversible resource consumption and any charge with the service owner. Check same-identity replay and ambiguous outcomes before asserting idempotence. |
| get_dragon_run | Existing identity. Returns status, standard results and ready artifact links. | Status retrieval; confirm effect of journal updates on classification. Repeated polls must not create another run. |
| stop_dragon_run | Identity and confirmation. Cancels a running operation. | Write and destructive. An ambiguous stop must not be replayed automatically. |

OpenAI requires explicit booleans for readOnlyHint, destructiveHint and openWorldHint. idempotentHint should match repeated side effects when supplied. The guidelines explicitly remove annotation justifications, while the error reference still lists justification_required. Keep the rationale above available if the portal asks. The official guidelines also require accurate descriptions of side effects. Capture the actual findings for both public servers before claiming compliance.
